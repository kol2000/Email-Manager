## Windows

Распакуйте весь ZIP и запустите EmailManager.exe. Папка _internal должна оставаться рядом. Python для готовой сборки не нужен. Сборка не подписана цифровой подписью.

Русский включён по умолчанию. Переключение: кнопка RU / EN слева внизу или Настройки → Язык. Во время активной операции дождитесь её завершения перед переключением.

## Импорт

Один аккаунт на строку: `email----password----client_id----refresh_token`.
Обычные IMAP-аккаунты: `email----password`. Разделитель — четыре дефиса. Настоящие данные аккаунтов не входят в исходники и сборку.

Исходный механизм OAuth использует Graph/Outlook API: токены только с IMAP-разрешениями могут не подойти. Локализация не меняет авторизацию и не гарантирует работу старых Outlook REST API.

## Обновление и данные

Закройте старую программу. Сделайте резервную копию её папки data, затем скопируйте data рядом с новым EXE. Встроенные статусы и название группы по умолчанию преобразуются автоматически. Пользовательские группы, заметки, письма и учётные данные сохраняются.

Как в исходной программе, база data/emails.db хранит пароли и токены без шифрования. Не загружайте её в GitHub и не отправляйте вместе со сборкой. Настройки показывают фактический путь к базе.

## Разработка (Windows x64, Python 3.10)

```powershell
py -3.10 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app\main.py
.venv\Scripts\python.exe -m unittest discover -s tests -v
.\build.ps1
```

Результат сборки: dist/EmailManager и dist/EmailManager-Windows-x64.zip.

## Проверки

Проверены переключение языков, ключи и параметры перевода, окна обоих языков, миграция старой базы, импорт тестовой строки и обновление токена с имитацией ответа Microsoft. Упакованный EXE запущен в Windows. Вход в реальную почту и отправка писем не проверялись.
